# Part 3 方向对照：当前实现与实际验证范围

## 当前能下什么结论

原方案选择作业方向 **A：Flow-Guided Fusion**，增加可靠性门控、边缘保护、尺度锚定和重置。
原有代码与 A0–A6 消融全部保留。本轮另实现 B/C/D/E/F 和 B+C+D 组合，没有根据结果删除较差方向。

**已完成的是 CPU 合成对照，不是真实模型效果验证。** 仓库的 Part 2 目前只有官方模型适配代码：
没有 `third_party/` 模型源码，`checkpoints/` 和 `data/` 只有说明文件，因而不能运行实际模型。
按用户要求跳过缺失数据/权重的真实推理，GPU 阶段暂不执行；未下载大模型或修改 Conda 环境。

## 可复现实验

命令：

```powershell
conda activate pytorch_env
python -m scripts.compare_part3_synthetic --output outputs/part3/directions_synthetic_new
```

本轮正式保存目录：`outputs/part3/directions_synthetic_final/`。
此前的 `directions_synthetic/` 是初轮结果；本记录使用 final 目录。

- 五类场景：static_noise、scale_bias、moving_occlusion、threshold_jitter、scene_cut。
- 每类 12 帧，64×96，10 FPS；NumPy 固定种子从 20261021 开始。
- 一共 60 个测试帧；每类另有三个独立生成的标定帧。
- 所有方向共享该场景的 RGB、原始预测、GT、有效像素和全分辨率评分光流。
- B 的测量值是独立标定场景的模拟真实距离，不取测试帧 GT；测试和标定 sample ID 不重叠。
- 计时：CPU、一轮预热、三轮完整处理，包含所需光流与预警计算，排除模型/解码/写盘/评分。
- 单个合成场景内的相邻帧有关联，不用逐帧 bootstrap 声称统计显著性。
- 融合和评分当前都用 Farneback，不属于独立光流交叉验证。真实实验可切换 RAFT 评分。

逐方法原始数组、固定色标视频、逐图指标、逐帧时序指标、预警结果均保留。
所有场景合并的观察值见 final 目录的 `all_scenarios.csv`，各场景的获胜指标见 `summary.json`。
不能把这些数值写成 NYUv2/KITTI 或正式 Part 2 模型结果。

## A：原方法的真实结果

在 static_noise 场景：原始预测 AbsRel=0.064278、时序 log-error=0.090790；A 输出相同。
`comparison/A/processing_diagnostics.json` 记录历史重置 11 次、平均历史融合权重 0。
静态 RGB 不变，因此这里是可靠像素比例过低触发重置；当前深度边缘阈值将大量噪声判成边缘，
膨胀后几乎没有可靠传播区域。保守门控保护了边界，但也放弃了消除噪声。

在 moving_occlusion 场景：A 的时序误差从 0.064268 降至 0.063547，改善幅度较小。
这些负结果原样保留，没有在测试场景上重新调 A 的阈值后替换结果。

## 其他方向结果

**B：最适合校正整体尺度偏差，需要额外测点。**
scale_bias 场景设置 1.25 倍预测尺度：原始 AbsRel=0.251630，B 降至 0.063915。
它不消除像素噪声，恒定乘法尺度也不会降低相邻 log-depth 差。
在没有尺度偏差的场景，测点噪声可能使 B 略微退化，不能无条件启用。

**C：这五类合成数据中，不依赖额外标定信息的单方向精度最好。**
static_noise 的 AbsRel 从 0.064278 降至 0.021386；时序误差降至 0.030487。
moving_occlusion 的 AbsRel 从 0.036315 降至 0.010887；时序误差从 0.064268 降至 0.030270。
不过 C 没有消除整体尺度偏差：scale_bias 的 AbsRel 仍为 0.244843。
这些场景有清晰且与深度对应的 RGB 边界，真实纹理、反光和薄物体可能改变结论。

**D：静态噪声和阈值抖动中的时序表现较好。**
static_noise 的时序误差从 0.090790 降至 0.025513，下降约 71.9%，AbsRel=0.032534。
threshold_jitter 中 D 时序误差=0.020238，低于 C 的 0.036570 和 B+C+D 的 0.024854；
预警 F1 从原始 0.833333 升至 0.909091。
这不证明不确定性已经校准：当前默认使用局部残差方差的启发式估计。

**E：已经实现低分辨率/自适应光流，不保证本测试里更快。**
E 保留 A 的融合规则，因此 A 因门控而不融合时，E 也无法改善深度质量。
64×96 输入太小、调度与公共开销占比较大，逐轮耗时有明显波动，不能凭此次 FPS 宣布稳定加速。
需要在真实分辨率、固定机器负载下重新测速。没有完成 ONNX/量化，也没有主模型加速结论。

**F：滞回预警并非总是更好。**
F 不改变深度图。static_noise 中原始预警 F1=1，F 为 0.956522；threshold_jitter 中原始为
0.833333，F 为 0.769231。连续帧确认和退出阈值产生报警/解除延迟，降低召回率。
代码和负结果保留；真实预警任务还应评价首次报警延迟，不能只优化画面稳定性。

**B+C+D：有独立标定信息时值得保留的组合。**
static_noise：AbsRel=0.014115、时序误差=0.014812。
scale_bias：AbsRel=0.013946、时序误差=0.014488。
moving_occlusion：AbsRel=0.008886、时序误差=0.025809。
组合在这五类场景中都取得最低 AbsRel，但 threshold_jitter 的时序指标仍不如 D，且计算更多。
含额外标定信息的组合必须与不使用外部测点的方法分栏报告，不能当成完全同条件的胜利。

## 目前的选择与下一步

保留所有方向。下一轮真实视频优先验证 **C、D**：C 偏向瞬时精度/边界，D 偏向时序稳定。
有可靠独立标定距离时，再验证 B 与 B+C+D。A 需要在开发集分析门控可靠覆盖率后决定是否调阈值；
E 需要真实分辨率测速；F 需要把漏报/预警延迟纳入任务目标。

没有真实 Part 2 预测之前，不确定真实数据上的最佳方向，也不声称达到计划中的改进目标。
