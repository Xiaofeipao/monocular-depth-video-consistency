# Part 3 后续优化与验收：2026-10-29

## 采取的建议

上轮 C_fast 缩小邻域导致边缘指标退化，本轮实现 `C_cuda`：保留 C 的
5×5 联合 RGB/log-depth 权重和逆深度平均，使用 PyTorch CUDA FP32 并行计算。
保留孔洞、原分辨率和边界复制方式；没有降低精度、量化或修改模型。
原 C、C_fast、A–F 及组合保留，CPU 默认入口不变，显式选择 C_cuda 才启用。

同时执行上轮的独立片段复核建议：从已下载 TUM fr1/xyz 原始归档的首 RGB
时间戳后 10 秒开始准备 32 帧，重新执行真实 metric VDA CUDA 推理。
新片段与早期十六帧不重叠，没有使用新片段的 GT 调整滤波参数。
这仍是同一场景的时间分离复核，不是独立数据集或跨域证明。

## 实测结果

RTX 5060 Ti，`D:/Anaconda/envs/torch_py311/python.exe`，PyTorch 2.12.1+cu132。
固定 OpenCV/PyTorch CPU 线程为 1，两个任务串行；每个方法一轮预热、五轮计时。
计时包括主机/设备传输及预警计算，不包括模型、读写、视频解码或评测。

- 原 TUM16：C 3.8045 FPS，C_cuda 91.2447 FPS，约 **23.98 倍**。
  两者 AbsRel 均约 0.285366，边缘 F1 均为 0.091468；最大相对逐像素差
  7.75e-7，delta1 差约 2.69e-7，其余精度和时序差异更小。
- 后续 TUM32：C 4.0133 FPS，C_cuda 90.2874 FPS，约 **22.50 倍**。
  两者 AbsRel 均约 0.135447，边缘 F1 均为 0.166094；最大相对逐像素差
  8.34e-7，delta1 差约 1.36e-7。位姿 log-error 均约 0.0248214。
- 四组额外 CUDA 数值检查覆盖随机奇数尺寸、极小图、单像素和薄结构，包含
  NaN 与零值孔洞，均通过 rtol=2e-6、atol=2e-6 的 CPU/CUDA 一致性检查。
- 完整回归测试：100 passed、1 skipped，跳过项需要可选官方 DepthPro 源码。
  TUM 采样测试还覆盖了 offset、时间戳不重叠及样本 ID 不重叠。

该收益是 **C 后处理的 GPU 加速**，不是 VDA 主模型或完整视频系统加速。
单线程 CPU 设定用于本机可复现对照，不表示所有 CPU 实现或设备的性能上限。
本轮不改变最佳时序方向结论，也不声称增加了深度估计准确率。
