# 自录视频：Part 2 与 Part 3 的 CPU 对照

## 当前结论

四段短片段中，A、C、D、E 相比原始 metric VDA 均降低了时序误差，独立
RAFT 光流评分也支持这个方向。但这是稳定性收益，没有深度/位姿 GT，不能
证明距离精度提高，也不能检查是否通过既有的 δ1/AbsRel 精度约束。
相机运动会导致同一物体的真实深度变化，本实验未用位姿更新 z；因此 warp 残差
也不是纯闪烁或真实尺度漂移。静止相机、静止场景的片段更适合支持闪烁判断。
与论文 TAE/GT 对齐协议的差异见 [论文审查](paper_comparison.md)。

视频 CPU 使用优先考虑 **E_half**：时序改善接近 A，后处理约快 1.7–2.3 倍。
**D** 在这次各片段的时序分数最低，但仍保留为探索结果，不据此推翻它在
既有 TUM GT 测试中精度损失超标的结论。**C** 的时序收益较小；完整 NYUv2
上的边界改进依然有效，但不能直接推广到这些低分辨率视频的每条细椅腿。

## 数据与协议

复用 `outputs/self_recorded_review/` 保存的同一组 RGB 与采样时间：每段 16 帧、
5 FPS、约 3 秒；RGB 长边 448，网络 input-size 252。
此前 DAV2/VDA 对照使用相对逆深度，不能将其直接当作米制深度送入现有后处理。
本实验因此使用官方 **metric VDA-Small** 权重重新推理同帧，全部 CPU FP32。
对照 RAW、A、A_conservative、C、D、D_guarded、E_half、E_local，参数固定，
没有针对这四段搜索参数。

融合使用 Farneback；评分同时使用 Farneback 和独立的 torchvision RAFT-Small。
每一帧对采用所有方法共同的前后向一致性掩码（1 像素阈值）、边界内、有限且正的
深度区域。均值为 15 个帧对的等权平均，没有逐帧尺度对齐。
时序指标为 `mean(abs(log(current)-log(warp(previous))))`，越低越好。

## 独立 RAFT 评分

以下为相对于同片段 RAW 的时序 log-error 降幅，顺序为 A / C / D / E_half：

- 横屏静态，9.67–12.67 秒：**11.49% / 3.98% / 15.31% / 11.47%**。
- 竖屏静态，6.67–9.67 秒：**13.55% / 4.90% / 15.26% / 13.50%**。
- 相机移动，11.29–14.31 秒：**11.11% / 3.67% / 17.00% / 11.66%**。
- 人物走动，7.43–10.43 秒：**8.59% / 1.85% / 12.60% / 8.38%**。

Farneback 评分也全部改善：A 为 8.61–17.89%，C 为 1.96–3.51%，
D 为 13.43–22.94%，E_half 为 8.00–17.61%。两种光流所得绝对分数与有效区域
不同，只在同一评分后端、同一片段内比较方法。

A_conservative 的 RAFT 改善约 4.57–7.49%，代价更保守。
D_guarded 为 8.34–10.43%，小于原 D。
E_local 在静态段与 E_half 相同；运动/人物段会切回全分辨率光流，结果接近或等同 A，
本次 CPU 后处理速度没有优于固定半分辨率版本。

## 细节与速度

统一 0.1–10 m 的可视化中，主要桌椅、人物和背景结构相近，改进以较小的时序
变化为主，不是结构重建出现明显跃升。低分辨率下仍有细结构和遮挡边界损失。

仅作为与 RAW 的结构诊断：A、E_half 在固定 log-depth 边缘阈值 0.08、容差
1 像素下保留了全部 RAW 边缘邻域；C 的保留率约 94.4–96.2%，检测边缘数量
为 RAW 的约 78.1–82.0%。这可能包含去噪与结构平滑，RAW 不是 GT，不能把这些
数字当作真正的边界召回率或断言全部损失都是错误。D 保留约 98.9–99.9%。

CPU 后处理实测：A 约 19.9–22.2 FPS，E_half 约 38.5–47.5 FPS，
C 约 14.5–15.7 FPS。每个方法一次预热、三次独立整段计时；OpenCV 单线程，
计入融合光流和预警计算，不含基础模型、读写、解码、可视化与评分。
这些不是整套系统的 FPS，也不是通用硬件速度结论。

## 复现与证据

```powershell
. ./scripts/project_cache.ps1
$env:PYTHONPATH = '.runtime'
$env:OMP_NUM_THREADS = '4'
$env:MKL_NUM_THREADS = '4'
$env:OPENBLAS_NUM_THREADS = '4'
python scripts/compare_self_recorded_part3.py
```

需已有四段 capture 检查与本地模型源码/权重。主输出为
`outputs/self_recorded_part3_cpu/`，包括命令、参数及源码哈希、原始/派生 NPY、
RGB/valid、配置/环境/计时、源视频校验值、采样时间、逐对 CSV、完整光流及共同
掩码、诊断和同范围比较视频。数值副本在 `docs/evidence/self_recorded_part3_cpu/`。
视频中的颜色为米制深度：蓝色近，红色远，所有方法和帧使用相同固定范围。

仍需完整片段、更高分辨率和跨窗口验证。16 帧在官方 VDA 内使用末帧填充至
32 帧；未做人物分割；平滑可降低时序分数但不一定提高真实精度。
现有室内自录片段也不构成跨场景泛化或统计显著性的证据。
